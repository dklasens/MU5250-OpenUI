v2.5 adds eSIM profile management, shows the modem's cell-lock state, and makes
the on-device agent hold up under stalled clients, hung firmware services and
panics. It also carries the dashboard accuracy and accessibility work done since
v2.4. Agent, dashboard and installer packages are versioned 2.5.0.

### SIM Management (eSIM)

- With a removable eUICC (an eSIM card in the SIM slot), Modem → SIM lists the
  profiles on the card and can enable, disable, rename, lock, download (by
  activation code or QR image) and delete them, and deliver operator receipts.
  The page is hidden when an ordinary SIM is in the slot.
- Card access runs through a new on-demand helper, `zte-esim`, deployed next to
  the agent. One card operation runs at a time, writes are never retried, and a
  lost answer is settled by reading the card back.
- Enabling, disabling, locking, downloading and deleting profiles, and sending
  receipts, need a password session; a PIN session is not enough. Card
  identifiers stay on the device.
- `zte-esim` links the LGPL-2.1 `euicc` library. Its license and
  `THIRD_PARTY_NOTICES.md` ship with the release.

### Cell-lock state

Signal → Mode & Locking now shows the cell lock the modem holds, per RAT:
unknown, none, or the locked cell (PCI, ARFCN and, for NR, band), and whether the
modem is on that cell. A lock to a cell the modem is not on shows a warning with
Reset beside it. The state always comes from the device's next read, never from
the request just sent.

### Agent resilience

- A client that stalls or trickles a request body is cut off with a 408 after
  10 s and no longer occupies an HTTP worker. At most eight uploads are read at
  once (503 beyond). Previously four stalled uploads took the API down until the
  agent was restarted.
- A hung firmware service no longer blocks every request. While one request
  refreshes a source, the others get the last good value, marked stale. Failing
  sources are retried with backoff up to 30 s, and heartbeat reads give up after
  3 s instead of 10 s.
- Panics are logged with their location and contained: the request gets a 500
  and the worker keeps serving. The event listener, loggers, diagnostics log and
  charge enforcer survive a panic.
- A stalled or oversized upload now has its connection closed, so a client may
  see a reset instead of the 408 or 413.

### Fewer subprocesses

The client list, Wi-Fi station data, TTL status and process list are cached for
a few seconds and invalidated by Wi-Fi, LAN and TTL changes. The LAN read is one
`uci show` instead of six calls and reports a failed read as an error instead of
empty values. Wi-Fi configuration is still read live, so read-back verification
after a change is never served from a cache.

### Metrics tab

CPU and memory come from the `/api/dashboard` heartbeat instead of their own
polls. Temperatures, battery and the fuel gauge each show their own error or
stale state with Retry, so one failing source no longer blanks the tab. The tab
makes about a third fewer requests.

### Signal ratings changed (not the radio)

RSRP, RSRQ and SINR now follow one policy (`web-app/src/data/signalQuality.ts`)
used by Home, Signal, the tables and the legend. Lower bounds are inclusive.

| Metric | Excellent | Good | Fair | Poor |
|---|---|---|---|---|
| RSRP, dBm | >= -80 | -90 to -80 | -100 to -90 | < -100 |
| RSRQ, dB | >= -10 | -15 to -10 | -20 to -15 | < -20 |
| SINR, dB | >= 20 | 10 to 20 | 0 to 10 | < 0 |

A reading that was orange before can be green now. For example, RSRQ -11 dB was
rated fair and is now good. The policy changed; the radio did not. RSSI is
shown but not rated. A missing measurement shows "Unavailable".

### Displayed values

- Home and Signal use the validated primary carrier: SA shows the NR PCC, LTE
  and NSA show the LTE anchor PCC. Unknown bars and measurements show
  Unavailable instead of a guess.
- Data usage counters can be unknown and are no longer shown as 0. The cycle
  block is "Current cycle". Reset day, enablement and the next reset date come
  from the device (both firmware date formats are read). `since_power_on` is
  shown as "Connection counters" because the firmware's `real_*` values reset
  with the data connection. Saving a reset day also enables automatic reset,
  and the button says so.
- Band locks distinguish unknown, automatic and locked. NR SA and NSA locks are
  read separately. A lock covering every supported band shows "All bands".
  Known limitation: the modem's default LTE mask covers 22 bands while the agent
  lists 24 lockable LTE bands (B66 and B71 are extra), so the device's default
  LTE state shows 22 bands selected, not "All bands".
- Wi-Fi TX power shows the real percentage (1-100). Channel widths are compared
  numerically, and channel advice is limited to configuration facts.
- USB: the Debug (ADB) option is removed. Capabilities decide which modes are
  offered. Active, scheduled and boot-default modes are shown separately.
  Verification is bounded and never resends the request.

### Safer editing

- Drafts survive polling: band selections, per-band Wi-Fi fields, the charge
  limit (now Apply / Cancel), TTL, network mode and APN mode.
- Connection-dropping actions are confirmed before they are sent: Wi-Fi off,
  per-band changes, save and sync; APN mode and activation; network mode; band
  lock and reset; cell lock and reset; USB mode; LAN. The reviewed payload is
  frozen. The UI reports accepted and verified separately, and never retries
  automatically. Cell-lock requests are unchanged apart from the confirmation
  and layout.
- SMS keeps one message collection; Inbox and Sent are views of it. Alerts have
  stable ids, dismissal lasts for the episode, and only a new episode or an
  escalation is announced.

### Resource model

`usePoll` and the new one-shot `useResource` report `loading`, `ready`, `error`
or `stale`, never show a previous key's data after a key change, and have their
cache cleared on logout and auth expiry. `/api/dashboard` remains the only
heartbeat (3 s on Home, Signal and System → Metrics, 15 s elsewhere).

### Accessibility

Native dialog confirmations with Cancel focused first for danger and connection
actions; tabs with roving focus and manual activation; radiogroups and
`aria-pressed` chips; labelled fields; live-region toasts where errors persist
until dismissed; a focus ring of at least 3:1; 44 px touch targets on coarse
pointers; stacked rows on phones.

### Agent

`data_usage.reset_day` and `reset_enabled` are `null` when neither ubus nor UCI
supplies a valid value. They were previously reported as `1` and `0`, which the
device never said. Clients that read these fields must handle `null`
([AGENT.md](../AGENT.md)).

### Tooling

- Playwright browser harness (`npm run test:browser`, `PW_PORT`, Chromium only,
  `@playwright/test` 1.63.0) now runs in CI. It cannot reach a real agent.
- `scripts/check-api-contract.py` compares method and path; the checker has its
  own tests (`tests/test_api_contract.py`).
- The mock agent (`web-app/tools/mock_agent.py`) is stateful and has
  `/__mock/requests`, `/__mock/reset` and `MOCK_SCENARIO`
  (`tests/test_mock_agent.py`).

Not included: a neighbour-cell list. On firmware HK B04 in 5G SA the firmware's
neighbour scan fails and drops mobile data for a few seconds, and the modem has
no AT query for NR neighbours.

### Downloads

- `zte-agent`, `zte-esim` and `dashboard-dist.tar.gz` contain the device
  application stack. The installers download and verify them.
- Installers: macOS 15+ Apple Silicon and Intel (`.dmg`, `.app.zip`), Windows
  x64 (setup EXE, MSI, portable ZIP). The installer workflow is unchanged from
  v2.4 apart from the version.
- **Signing:** Windows packages are unsigned. Mac packages are ad-hoc signed and
  are not Apple-notarized. Operating-system warnings may appear.
- `installer-wireframes.zip` contains labelled sample-data images.
- `sha256sums.txt` covers all published payload downloads.

### Unlock key

Locked devices still require their router admin password and compatible
backup-key suffix. The key is available in the
[upstream issue #8 discussion](https://github.com/jesther-ai/open-u60-pro/issues/8).
It is not embedded in the installers or copied into this repository.

### Validation and limits

- The agent resilience, caching, Metrics and cell-lock changes were deployed
  with the terminal deploy scripts to a physical MU5250 (firmware
  `XCBZ_HK_MU5250V1.0.0B04`) and checked there on 2026-11-14. With ten stalled
  uploads open, `/api/dashboard` answered in 17-32 ms and each upload was cut
  off at 10 s. The cell-lock formats were read from the same device.
- The hung-service and panic paths are covered by unit tests only; they were not
  provoked on the device.
- The desktop installers were not run against a physical modem for this
  release. Release checks cover Rust and UI tests and package startup checks.
- Power loss and force termination cannot be prevented; retain recovery
  snapshots and review the
  [safety guidance](https://github.com/dklasens/MU5250-OpenUI/blob/v2.5/docs/SAFETY.md).
- Dashboard/API traffic still uses HTTP on the LAN.

[Installer instructions](https://github.com/dklasens/MU5250-OpenUI/blob/v2.5/installer/README.md)
include platform prerequisites, offline use, credential preservation and recovery.
